# Hermes Agent Integration

## Recommended: Webhook Delivery

Sub-second latency, zero LLM cost, no background process required.

### Step 1 — Start Hermes Webhook Gateway

Hermes webhook platform config lives at `~/.hermes/config.yaml` under `display.platforms.webhook`:

```yaml
display:
  platforms:
    webhook:
      enabled: true
      extra:
        host: '0.0.0.0'
        port: 8644
        secret: 'your-webhook-secret-here'
```

Start the gateway:

```bash
hermes gateway run
# Or via systemd:
systemctl --user restart hermes-gateway
```

Verify it's running:

```bash
curl http://localhost:8644/health
```

### Step 2 — Create Hermes Webhook Subscription

Create a webhook subscription that forwards agent-comm messages to Telegram:

```bash
hermes webhook subscribe agent-comm-<YOUR_AGENT_NAME> \
  --deliver telegram \
  --deliver-chat-id "YOUR_CHAT_ID" \
  --deliver-only \
  --prompt "Message from {data.from_agent_name}: {data.content}"
```

This returns:

- A URL (e.g., `http://localhost:8644/api/webhooks/agent-comm-my-agent/uuid`)
- A secret (32-byte token, URL-safe base64 encoded)

**The secret is generated by Hermes — save it for the next step.**

### Step 3 — Register with agent-comm

Register the webhook using the URL and secret from Hermes:

```bash
COMM_USER=<YOUR_AGENT_NAME> $AC webhook register <URL_FROM_STEP_2> --secret <SECRET_FROM_STEP_2>
```

Example:

```bash
COMM_USER=ac-developer $AC webhook register \
  http://localhost:8644/api/webhooks/agent-comm-ac-developer/abc123 \
  --secret 8cc1081af6c5adac02d7c981bb09ad0122097cf14bfcc37ae113dcab4a694d34
```

### How It Works

When agent-comm receives a message for your agent, it POSTs a signed JSON payload to the Hermes webhook URL:

```json
{
  "event": "message:sent",
  "timestamp": "2026-04-21T12:00:00.000Z",
  "data": {
    "id": 42,
    "from_agent": "agent-uuid-1",
    "from_agent_name": "ac-developer",
    "to_agent": "agent-uuid-2",
    "to_agent_name": "Hermes-5",
    "channel_id": null,
    "content": "message text",
    "importance": "normal",
    "created_at": "2026-04-21T12:00:00.000Z"
  }
}
```

Headers:

- `X-Hub-Signature-256: sha256=<hex>` — HMAC-SHA256 signature (GitHub-style)
- `X-GitHub-Event: message:sent` — event type

### Signature Verification

Hermes webhook adapter supports three signature formats:

1. **`X-Hub-Signature-256: sha256=<hex>`** — GitHub-style (agent-comm uses this)
2. **`X-Gitlab-Token: <plain secret>`** — GitLab-style
3. **`X-Webhook-Signature: <hex>`** — Generic hex

To verify: `HMAC-SHA256(secret, requestBody) == hex_value`

### Prompt Template

The `--prompt` flag uses Python string format with dot-notation access:

- `{data.from_agent_name}` — sender name
- `{data.to_agent_name}` — recipient name
- `{data.content}` — message body
- `{data.importance}` — urgency level
- `{data.id}` — message ID
- `{data.created_at}` — timestamp

### Why Webhooks Over ac Watch

| Aspect                 | `ac watch` (background)   | Webhook delivery           |
| ---------------------- | ------------------------- | -------------------------- |
| Latency                | Broken `_reader_loop`     | Sub-second                 |
| LLM cost               | Requires agent turn       | Zero (deliver-only mode)   |
| Background process     | Yes (breaks)              | No                         |
| Reliability            | Depends on broken pipe    | Proven webhook platform    |
| Recovery after restart | Broken (stale checkpoint) | Automatic (stateless HTTP) |

**Note**: `_reader_loop` in Hermes background mode is broken for long-running processes — see `docs/HERMES.md` in the agent-comm repo for details.

## Legacy: ac Watch

Works but requires background process. Webhook delivery is the recommended alternative.

```python
terminal(background=True, notify_on_complete=True,
         watch_patterns=["[MSG]"],
         command='$AC watch --interval 60')
```

- `watch_patterns=["[MSG]"]` triggers notification on message arrival
- `notify_on_complete=True` is safety net (fires if process dies unexpectedly)
- One process, one lock — poll lock prevents duplicate watchers
- Process never exits — runs until killed or session ends
