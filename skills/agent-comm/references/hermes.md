# Hermes Agent Integration

Setup (identity, config, registration) is in the shared SKILL.md — follow that first.
This guide covers Hermes-specific communication patterns.

## Recommended: ac poll Loop

Hermes background `ac watch` is broken (`_reader_loop` bug). Webhooks can't target
a specific CLI session. The practical default is `ac poll` as a background process:

```python
# Poll for messages — blocks until one arrives (up to 30min), then returns it
terminal(background=True, notify_on_complete=True,
         command='source ~/.agent-comm/config.sh && $AC poll --timeout 1800')
```

**How it works:**

1. `ac poll --timeout 1800` blocks until a message arrives (or 30min timeout)
2. Returns the message as JSON (auto-marks as read)
3. Process exits — Hermes fires `notify_on_complete` with the output
4. Agent reads the message, decides what to do, responds if needed
5. Agent runs `ac poll` again to wait for the next message

**On timeout (exit code 1):** No message arrived in 30 minutes. Just re-run the poll — this is normal, not an error. The server caps individual polls at 60s, but the CLI loops internally to reach your requested timeout.

**Why this works:**

- Each poll is a short-lived process — no `_reader_loop` bug
- Message arrives in the current session context, agent can respond
- One poll at a time (fcntl flock prevents concurrent poll/watch)

### Sending Messages

```bash
$AC send target-agent 'Build complete, ready for review'
$AC send channel:ops 'Deploying to staging'
$AC broadcast 'All agents: sync meeting in 5 min'
```

### Checking Inbox

```bash
$AC inbox --unread     # show unread messages
$AC agents             # list online agents (auto-heartbeat)
```

### Quick Reference

```bash
# Send task
$AC send target-agent 'PR #42 ready for review'

# Wait for work (background poll)
$AC poll --timeout 1800

# Reply
$AC send target-agent 'PR #42 approved'
```

## Alternative: Webhook Delivery

For notifications to telegram (no agent session). Zero LLM cost, sub-second latency.

### Step 1 — Start Hermes Webhook Gateway

Config at `~/.hermes/config.yaml` under `display.platforms.webhook`:

```yaml
display:
  platforms:
    webhook:
      enabled: true
      extra:
        host: '0.0.0.0'
        port: 8644
        secret: 'your-webhook-secret-here'
```

```bash
hermes gateway run
# Verify: curl http://localhost:8644/health
```

### Step 2 — Create Hermes Webhook Subscription

```bash
hermes webhook subscribe agent-comm-<YOUR_AGENT_NAME> \
  --deliver telegram \
  --deliver-chat-id "YOUR_CHAT_ID" \
  --deliver-only \
  --prompt "Message from {data.from_agent_name}: {data.content}"
```

Returns URL + secret (generated by Hermes).

### Step 3 — Register with agent-comm

```bash
$AC webhook register <URL> --secret <SECRET>
```

### Limitations

- **No session context**: Pushes to telegram, agent can't respond in session
- **Not suitable for multi-repo coordination**: Cannot target a specific CLI session

Webhook is useful for monitoring/alerting. For coordinated agent work, use `ac poll`.

## Comparison

| Aspect          | `ac poll` loop (recommended) | Webhook `--deliver-only`   | `ac watch` (broken)   |
| --------------- | ---------------------------- | -------------------------- | --------------------- |
| Session context | Current CLI session          | None                       | Current CLI session   |
| LLM cost        | Zero (notification only)     | Zero                       | Zero                  |
| Agent can act   | Yes — in current session     | No — push to telegram      | Yes — if it worked    |
| Reliability     | Short-lived processes        | Stateless HTTP             | Broken `_reader_loop` |
| Setup           | None — just run poll         | Gateway + subscription     | Just run watch        |
| Multi-repo      | One poll per CLI session     | One subscription per agent | One watch per agent   |

## Legacy: ac Watch

Broken for Hermes background mode due to `_reader_loop` bug. Do not use.

**Note:** `ac watch` now outputs **JSON Lines** (implemented), but Hermes still cannot read it due to the `_reader_loop` bug.

```python
# BROKEN — do not use
terminal(background=True, notify_on_complete=True,
         watch_patterns=['"type":"msg"'],
         command='$AC watch --interval 60')
```

**Watch patterns** should match `"type":"msg"` instead of `[MSG]` (JSON Lines output).
